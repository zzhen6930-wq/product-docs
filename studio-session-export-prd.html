会话导出
产品需求文档

01目标与范围

为 Studio 会话管理补充单会话和批量 Excel 导出能力，支持用户离线查看对话、复盘执行过程和分析每轮耗时。

Studio 已具备按会话 ID 聚合的列表，以及展示私聊、群聊对话与执行事件的详情页；旧 Fabric 平台已有导出能力。此次在 Studio 内补齐导出闭环，不改变现有会话和 trace 的业务归属。

本期交付具体范围
导出入口仅提供列表行级导出和列表右上角批量导出；详情页不提供导出按钮。
内容选择可选保留对话过程事件，默认不保留；无需配置导出字段和范围。
文件结果生成 .xlsx，首列为会话 ID，每行是一轮用户输入及其相关信息、Agent 输出。
异步闭环后台生成，任务中心查看状态、下载、失败重试和过期重建。

本期不新增会话分析报表、定时导出、自定义字段配置或其他文件格式。原型中的模拟数据、固定进度和浏览器本地任务存储不属于生产实现要求。

01 / 范围确定会话单条、已勾选或筛选结果
02 / 内容选择是否保留事件默认只导出基础对话信息
03 / 任务后台异步生成提交后可继续使用 Studio
04 / 文件下载 Excel按 trace 逐行复盘

02入口与导出范围

批量导出的唯一判断规则：列表有勾选 → 导出勾选会话；列表无勾选 → 导出当前筛选结果，包含所有分页。弹窗内不再选择范围。
入口 / 条件导出对象说明
列表单行「导出」该行会话 ID忽略其他行的勾选状态。
批量导出 · 已勾选所有已勾选会话 ID包含跨页勾选结果，不扩大到未勾选会话。
批量导出 · 未勾选符合当前列表筛选的全部会话不是仅导出当前页；未设置筛选时，范围为当前空间下全部有权查看的会话。

列表选择规则

  • 表头复选框仅全选 / 取消选择当前页；翻页保留已选会话。
  • 列表展示已选数量，并提供「清空」及「选择全部筛选结果」。后者选中当前筛选条件下所有分页的结果。
  • 修改或重置筛选条件时清空已选，防止旧选择与新筛选混用；单纯翻页不清空。
  • 筛选条件沿用当前会话列表定义。列表时间筛选用于确定会话集合，不再次截取会话内部的 trace 时间范围。

范围固定与数据时点

打开导出弹窗时固定本次选择模式及对应会话 ID / 筛选条件；成功创建任务时解析最终会话集合，并以任务创建时刻作为数据截止时间。之后修改列表筛选、取消勾选或新增对话，不影响已创建任务。

截止时间规则用于明确异步导出的结果边界，是本 PRD 的产品补充规则。生产端需在任务生成时保证同一任务的数据口径一致。

03导出设置与提交

弹窗标题按入口展示「导出会话」或「批量导出会话」。正文仅保留「导出内容」，包含一个复选框。

元素规则
保留对话过程事件默认不勾选，每次打开弹窗恢复默认。勾选后追加实际事件类型列；取消勾选时不导出过程事件。
复选框说明「包含已记录的思考、模型调用、工具调用与系统事件。」
取消 / 关闭关闭弹窗，不创建任务，不改变列表的已选状态。
创建导出任务提交当前范围和内容选项。提交中按钮置为加载态并禁止重复点击；创建成功才关闭弹窗。

弹窗不展示范围选择、Excel 结构预览、字段解释或异步说明；不出现「每个事件独占一个单元格，按发生时间依次排列。」文案。

创建成功后提示「导出任务已创建，可继续浏览」，提供「查看进度」入口，跳转右侧导出任务面板。创建失败则保留弹窗和选择，展示原因并允许再次提交。

没有可导出的会话时禁用提交，并在列表空态提示调整筛选条件。一次有效提交只创建一个任务。

04Excel 数据结构

一行的定义

一行 = 一轮 trace：一条用户输入，以及该输入触发的 Agent 执行过程和最终回答。同一会话多轮对话分别占行；群聊中不同成员的输入按各自 trace 分行，不按成员合并。流式输出的分片合并为该轮完整回答，不拆成多行。

会话 ID → 智能体 → 应用场景 → Query 时间 → 耗时 → 用户 → 用户 Query → 可选事件类型列 → Agent 输出
字段名产品口径示例 / 空值
会话 ID始终为第一列。填写该 trace 所属的完整会话 ID，每行重复填写，不合并单元格。850c2fea-…
智能体该会话对应的智能体展示名称，与会话列表 / 详情页保持一致，不使用模型名称代替。WorkHub
应用场景该会话的实际应用场景，与会话列表一致。同一会话的每轮 trace 重复填写；不使用「来源」或智能体名称推断场景。仅允许：POPO单聊、POPO群聊、WorkHub、SDK。缺失或未知值不强行归类，导出失败并提示场景数据异常。
Query 时间该轮用户输入的时间，与详情页保持一致。统一使用 Studio 页面时区，格式 YYYY-MM-DD HH:mm:ss。2026-10-27 20:51:40
耗时该轮 trace 从用户输入到最终回答完成的总耗时，与详情页 trace 头部一致；不是首字耗时，也不是模型和工具耗时之和。3.7s、6.7s、68s；未完成填写「尚未完成」，已结束但缺失耗时填写「未记录」。不将缺失值写为 0。
用户触发该轮输入的用户标识，优先邮箱，无邮箱时沿用系统用户 ID。群聊填写实际输入者，不以群 ID 替代。member1@example.com
用户 Query完整用户输入正文，保留换行；已有附件名称、引用及链接按记录展示，不导出页面截断文案。帮我创建一个多维表格
事件类型列仅勾选保留事件时出现，按第 05 节规则展开。模型调用、工具调用 1…
Agent 输出该轮最终回答正文。尚未完成且无最终回答时填写「尚未完成」；失败且无最终回答时填写「执行失败（无最终回答）」。正常结束但无回答记录时填写「无输出」。已创建「需求跟踪表」…
智能体、应用场景和耗时始终导出。不勾选保留事件时，仍包含完整的 8 个固定字段；仅移除可选事件列。

文件与排序

  • 标准结果为一个 .xlsx 文件，多个会话汇总在同一「会话对话」工作表。
  • 第一行是字段名（A1 为「会话 ID」），从第二行开始是 trace 数据。会话 ID 升序排列，组内按 Query 时间升序；时间相同时沿用原始 trace 顺序。
  • 固定字段按上述顺序展示，事件列插在用户 Query 和 Agent 输出之间。冻结首行和首列、开启表头筛选，文本自动换行。
  • 文件名：会话导出_YYYYMMDD_HHmmss_任务短编号.xlsx；批量导出使用「会话批量导出」前缀，避免同名文件难以区分。
  • 用户输入、工具返回等按文本写入 Excel，不执行内容中的公式；长 ID 不转换为科学计数法。

05事件列展开规则

表头使用真实事件类型，不再使用「过程事件 1 / 2 / 3」。事件数据与 trace 绑定，每个事件占一个单元格。

事件类型与内容

事件类型名称导出内容口径
用户输入trace 内额外记录的输入事件。作为该轮起点的用户输入已在「用户 Query」中，不重复追加。
模型调用已记录的模型调用信息及可见思考内容；思考归入此类型，不另造「思考」表头。
工具调用 / MCP / Skills沿用原始事件分类，包含名称、输入参数、返回内容和执行状态。一次调用的输入和返回保留在同一个单元格。
上下文压缩 / 系统信息已记录的压缩事件说明、系统状态等内容。
Agent执行中的 Agent 中间消息。作为最终回答的记录已在「Agent 输出」中，不重复追加。
报错信息已记录的错误类型、错误信息和关联执行对象。

仅导出真实已记录且用户有权查看的内容，不补造思考、参数或返回值。未出现的类型不生成空列。记录本身为空时填写「无记录内容」，以区别于该行没有此事件的空单元格。

同类多次出现，以及不同 trace 的顺序差异

  1. 先按各 trace 内事件时间顺序排列；时间相同则沿用原始事件顺序。
  2. 根据本次导出的所有 trace，形成一组能容纳各行事件顺序的公共列。每列仅承载同一种事件类型。
  3. 同一类型只有一列时使用原名称；有多列时按列从左到右编号，例如「工具调用 1」「工具调用 2」。编号用于区分导出列，不代表所有行都有第 N 次调用。
  4. 每行从左到右填入与列类型匹配的事件，缺失位置留空。不得把多个调用拼到一个单元格，也不得为对齐表头打乱该轮事件顺序。
  5. 不同 trace 的类型顺序不一致时，允许增加同类型列。不能仅按事件位置直接改名，否则可能出现“模型调用”列下填入“工具调用”。

以下仅展示事件区域；正式文件左右仍保留固定字段。空白表示该行此位置没有事件。

trace 原始顺序模型调用 1工具调用模型调用 2
A：模型 → 工具模型调用内容 A工具调用内容 A—
B：工具 → 模型—工具调用内容 B模型调用内容 B

该示例强调类型与时间顺序同时成立，不要求不同导出文件使用完全相同的事件列数量。

06异步导出任务

任务创建后由服务端持续执行。用户关闭弹窗、收起任务面板、离开会话页或关闭浏览器，都不终止任务；再次进入时可查询任务状态。原型约十秒完成的演示节奏不作为实际耗时承诺。

入口与任务展示

会话列表和详情页右上角提供「导出任务」，打开右侧任务面板。仅展示本人在当前空间创建的任务，按创建时间倒序排列。提供「全部 / 进行中 / 已完成 / 失败」筛选；进行中包含排队和生成，已过期任务在「全部」中保留。

每项任务展示任务名称、会话数量、是否保留事件、文件格式、创建时间、当前状态及对应操作。任务实际范围在创建后固定，会话数量不受后续列表变化影响。

状态含义与展示操作 / 下一状态
排队中任务已创建，等待后台处理。等待进入生成中；异常可进入导出失败。
生成中正在整理会话与文件。仅在能获得真实进度时展示百分比，否则展示生成中。成功进入已完成；异常进入导出失败。
已完成文件已生成且可下载；展示剩余有效期。「下载文件」；到期进入已过期。
导出失败展示可理解的失败原因，不提供残缺文件下载。「重新导出」，创建新任务，原失败记录保留。
已过期文件超过有效期，原下载链接失效。「重新创建」，创建新任务，原记录保留。

完成、有效期与重新创建

  • 当前页面内任务完成时提示「导出已完成」，提供前往下载入口。任务结果以任务中心为准，不依赖提示是否被看到。
  • 文件有效期为生成成功后 7 × 24 小时，按完成时间起算；排队时间不消耗文件有效期。本规则明确原型“保留 7 天”的生产口径。
  • 失败重试 / 过期重建复用原任务已解析的会话 ID 集合及事件开关，不重新扩大为当前筛选范围；重新校验权限，以新任务创建时间作为新的数据截止时间。
  • 重新下载同一个有效任务获取同一份结果；重新创建任务可能包含新增 trace，因此文件内容可能变化。

07边界与异常

以下补充规则用于避免异步任务结果不完整、范围变化或数据口径误解；其中容量阈值仍需评审确定。

场景处理规则
没有匹配会话不创建空任务，提示「暂无可导出的会话，请调整筛选条件」。
会话存在但无 trace该会话不生成数据行；任务完成信息说明无可导出对话的会话数量。全部无 trace 时失败并说明原因，不返回仅含表头的成功文件。
trace 仍在执行按截止时间导出已记录的输入和事件；耗时填「尚未完成」。无最终回答时 Agent 输出同样标记，不等待该轮结束。
trace 执行失败保留该轮数据；已记录总耗时可正常填写。勾选保留事件时输出报错信息，无最终回答时按第 04 节标记。
任务创建请求失败保留弹窗选项，提示重试；避免网络重试产生重复任务。
权限变化 / 会话删除创建、生成和下载时检查权限。生成时目标会话不可读取则任务失败，明确提示；不得静默减少会话范围。下载时权限已失效则阻止下载。
下载失败但文件有效提示重试下载，不创建新导出任务，不改变原已完成状态。
单元格、行数或列数超出格式限制不得静默截断内容、丢弃事件或将多个事件合并。超限文件的分片方案及任务上限待确认；方案确定前按失败处理，并提示缩小范围。单事件超长不能仅靠缩小会话范围解决，需明确说明该原因。

09待确认事项

本节不改变已确认的核心交互。以下内容原型未给出完整依据，需要产品与研发在排期前明确；不得以演示数据规模作为实际限制。
待确认项需要明确的决策
单次容量与并发单次最大会话 / trace / 文件规模、个人并发任务数、任务超时与排队策略；超限提示保持可理解。
超大内容处理原型说明提出分片和索引，但未演示具体形式。需确定超长事件如何完整交付且仍能定位到 trace，以及是否引入分卷或附属文件。
任务记录保留期限文件有效期已明确为完成后 7 天；过期任务记录在任务中心保留多久，需另行确定。
权限与数据字段映射确认沿用现有会话查看权限是否足够，以及现有 trace 总耗时、最终回答、终态、事件归属字段能否支撑本 PRD 口径。

已确认需求以本次用户修订为准：弹窗精简、自动确定批量范围、使用事件类型表头、新增耗时、智能体和应用场景，取消详情页导出按钮。本 PRD 为异常值、快照和有效期补充了明确规则，评审通过后作为开发与验收依据。
