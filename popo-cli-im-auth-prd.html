01需求总览

需求用户问题目标结果
读取表情用户常用表情表示“收到”，Agent 读取消息时遗漏这类反馈。能知道谁对哪条消息做了什么表情回应，保留可用于判断的上下文。
本人发送表情已有机器人表情能力，缺少本人身份操作。用户说“用我的身份回复”，能以当前登录账号完成表情操作。
提前授权提醒任务运行时才发现缺权限；用户未及时授权，自动化中断。用户主动使用 CLI 时检查，剩余有效期在 25～48 小时内推送提前续期卡片。
图片／文件／视频检索纯图片、视频及文件消息需要独立检索能力。图片／视频复用客户端分类能力；文件直接通过服务端大搜检索。
GRP 检索优化未安装并启动 daemon 时无法检索 GRP 消息，需要用户手动处理。将状态检查与按需安装启动写入 Skill，由 Agent 完成前置步骤。

用户原声：“用表情代表【收到】的情况很多，对 Agent 自动化来说这些信息非常需要。”

事实边界：本地 IM Skill 参考支持机器人对已有消息添加／取消表情回应；本人发送的首期范围以本次确认的 12 种系统表情为准。独立表情消息与消息下方的表情回应需分开设计。下文为产品方案，待确认项不代表现有能力。

02IM Skill：读取表情

规则

规则产品要求
覆盖范围本期仅支持读取已有消息上的表情回应；不包含独立表情消息和文字混合表情。
返回信息表情回应保留目标消息、回应者、表情。
搜索消息读取、上下文读取返回表情回应；消息搜索命中后返回关联表情回应信息。支持按已知系统表情名称查询表情回应。
覆盖表情首期优先支持现有 12 种系统表情（玫瑰、OK、有了、get、ing、1、Done、握手、+1、No、666、强）。

03IM Skill：以本人身份发送表情

场景预期行为
“给这条消息点个赞”以当前登录用户身份给目标消息添加表情回应；支持取消本人回应。
“给张三发一个收到的表情”发送一条独立系统表情消息。属于新增消息发送能力，不能用消息回应冒充完成。
“用机器人 XX 回应”沿用机器人身份能力。本人操作失败时不自动切换机器人。

执行规则

  • 身份：明确“我／本人”时使用当前登录账号；未指定身份时按本人处理，Skill 说明中明示该默认值。
  • 目标：发送前确定会话；表情回应还须确定具体消息。多人同名、多条消息或表情含义不明确时，先澄清。
  • 范围：首期优先支持现有 12 种系统表情（玫瑰、OK、有了、get、ing、1、Done、握手、+1、No、666、强）。

本期不含自定义表情上传、表情包管理，以及自动替用户表达同意／审批。

04应用授权：提前一天提醒

规则产品要求
触发时机用户主动使用 CLI 时，校验应用授权是否满足提前推送续期卡片的时间范围。
提醒时间暂定为授权到期前 48～25 小时，即剩余有效期满足 25 小时 ≤ 剩余有效期 ≤ 48 小时时，推送续期卡片。
范围外处理剩余有效期大于 48 小时或小于 25 小时，不触发本次提前续期提醒；未主动使用 CLI 时不触发该检查。
新建续期卡片标题改为「POPO-CLI提前续期」；权限说明改为「POPO-CLI以下访问权限即将过期」。其余内容与交互沿用现有授权卡片；授权有效期选项按下方统一规则调整。
授权有效期选项「提前续期卡片」和「请求授权卡片（当前的授权卡片）」统一提供：5分钟、1天、7天、30天。

续期卡片文案示意

  • 云文档、表格、多维表格
  • 日历、会议室

请求来源：沿用现有卡片字段

○ 5分钟　 ○ 1天　 ○ 7天　 ○ 30天

确认 拒绝

静态文案示意；权限列表按实际即将过期的授权展示，两类卡片的有效期选项统一为 5分钟、1天、7天、30天；其余字段及确认／拒绝交互沿用现有卡片。

05IM Skill：支持获取纯图片、文件、视频消息

规则产品要求
覆盖范围支持检索纯图片、视频及文件消息；纯图片／视频没有文字内容时，也能按消息类别获取。
图片／视频图片、视频在服务端均属于文本消息类型，不能仅按服务端消息类型区分。复用 POPO 客户端“图片和视频”分类检索能力，支持获取对应消息。
客户端依赖需研发确认图片／视频检索是否依赖客户端与 daemon。若依赖，将下方 GRP 同款前置流程写入对应 Skill：先执行 popo-cli daemon status，未启动才执行 popo-cli daemon install。
文件文件属于独立文件消息类型，通过服务端大搜接口直接提供检索能力；不依赖客户端，不触发 daemon 安装启动。
结果展示返回对应消息及可用的图片／视频／文件资源引用，保留发送者、时间、会话与消息标识。资源不可用时明确提示，不将检索失败表述为“没有消息”。

依据用户提供的客户端截图：“聊天记录”支持“消息”“文件”“图片和视频”分类。客户端能力的可调用方式及依赖条件待研发确认。

06IM Skill：检索 GRP 机器人消息优化

当前限制：必须完成 popo-cli daemon install（安装＋启动）后才能检索 GRP 消息。

Skill 执行流程

识别 GRP 检索需求 → daemon status → 已启动：直接检索
未启动：daemon install → 确认启动成功 → 继续检索
规则产品要求
前置检查将 popo-cli daemon status 写入 GRP 消息检索 Skill，Agent 检索前先检查运行状态。
按需安装启动先执行 popo-cli daemon status，未启动才执行 popo-cli daemon install。
完成后继续安装启动有耗时，Agent 提示正在准备检索环境，等待启动成功后继续原检索任务。状态查询失败时不能直接认定“未启动”；安装或启动失败时明确反馈原因，不继续检索。
复用范围若图片／视频检索确认依赖 daemon，复用该前置流程；文件大搜不走此流程。

重点测试

  • 首次耗时：分别记录首次安装＋启动耗时、就绪后的检索耗时和整体等待时间；以实测结果确定体验优化要求，不预设耗时承诺。
  • 短暂断联：重点观察安装启动是否造成工作伙伴短时间断联，记录是否发生、持续时间及能否自动恢复；恢复后检查原检索任务能否继续。
  • 状态分支：覆盖未安装、已安装未启动、已启动、状态查询失败、安装失败与启动失败。已启动时不得重复安装。

07验收标准

场景通过标准
读取确认表情仅验收已有消息上的表情回应读取；正确返回目标消息、回应者、表情，不包含独立表情消息和文字混合表情。
避免误判返回表情事实及上下文；未知表情明确标记，点赞或“收到”不被直接写成任务完成。
回应取消取消后再次读取不计入有效回应；同一用户不会重复计数。
本人身份对方实际看到的发送者／回应者为当前登录用户；机器人发送行为保持原身份。
两类发送“发一个表情”产生新消息；“对这条点个赞”产生回应；取消只影响本人回应。
失败与重试无权限、不支持表情、目标不明均有明确结果；重试不产生重复消息或回应。
纯图片／视频无文字内容的图片／视频消息也能检索到，类别与客户端一致；依赖 daemon 时正确执行前置检查。
文件服务端检索客户端未运行且 daemon 未启动时，文件仍可通过大搜返回，不触发 daemon install。
GRP 前置流程先 status，未启动才 install；启动成功后继续检索，已启动时直接检索。
耗时与断联测试报告包含首次安装启动及端到端耗时；记录工作伙伴断联情况、恢复时间和原任务恢复结果，异常须跟踪处理。
续期触发用户主动使用 CLI 时校验剩余有效期；无主动使用行为时不触发提前续期检查。
时间窗口剩余 25 小时、48 小时及两者之间时推送续期卡片；小于 25 小时或大于 48 小时不推送。
卡片文案标题为「POPO-CLI提前续期」，说明为「POPO-CLI以下访问权限即将过期」；其余字段与确认／拒绝交互沿用现有卡片。
两类卡片有效期提前续期卡片与当前请求授权卡片均按顺序展示 5分钟、1天、7天、30天；不再展示 14天选项，提交后授权有效期与所选值一致。

上线观察

关注：系统表情可识别率、本人表情操作成功率、授权提醒投递成功率、任务开始前授权完成率，以及因权限不足导致的任务中断率。首期采集基线，后续确定改善目标。

08评审需确定的事项

决策建议与依赖
表情范围读取范围已确定为表情回应；本人发送仍按对应章节定义，确认其两类操作的底层支持。
授权检查依赖确认用户主动使用 CLI 时可获取应用授权到期时间，并按剩余有效期判断是否进入 25～48 小时续期窗口。
媒体检索依赖确认客户端图片／视频分类能力的调用方式、daemon 依赖及客户端运行要求；据此更新对应 Skill 前置流程。
