AgentHub · 发现页支持多租户提供技能与工具

发现页由「仅 POPO 租户供给」扩展为「POPO 租户 + Agent 归属租户」双来源供给；其他租户在 Studio 后台上架的 Skills / MCP，仅在其归属租户的 Agent 发现页展示，实现租户级隔离。
📅 2026-09-13 🏷️ v1.0 👤 作者：青远（张振） 🧩 归属：AgentHub · 技能和工具 / WorkHub Studio
1背景与问题

AgentHub 中用户为 Agent 绑定的技能（Skills）与工具（MCP）不足时，可通过「添加技能 / 添加工具 → 发现」页选择更多能力。

现状

  • 发现页只展示 POPO 租户（官方租户）在 Studio 后台上架的 Skills / MCP。
  • 其他租户即使在 Studio 后台配置了 Skills / MCP，也不会在发现页展示。
  • AgentHub 已支持其他租户在 Studio 后台配置 Agent 并设置可见性，其租户用户进入 AgentHub 可直接使用租户提供的 Agent。

问题

⚠️ 核心问题
当其他租户提供的 Agent（如易协作租户）所绑定的技能 / 工具不足时，用户在发现页只能看到 POPO 租户提供的通用能力，看不到本租户提供的垂直领域技能与工具，导致租户垂类能力无法被补充绑定，租户侧供给白建。

目标

  • 支持其他租户也能把在 Studio 后台上架的 Skills / MCP 供给到 AgentHub 发现页。
  • 供给严格按租户隔离：只在归属该租户的 Agent 的发现页展示，不影响其他租户用户。
🔑 一句话定位
发现页供给 = POPO 租户（全局） + Agent 归属租户（局部）；租户能力只对本租户 Agent 可见。
2供给来源与展示规则

2.1 双来源供给

来源供给范围说明
POPO 租户（官方）全部 Agent官方通用能力，所有 Agent 的发现页均展示，逻辑不变。
其他租户（如易协作）仅归属该租户的 Agent租户在 Studio 后台上架的 Skills / MCP，仅在归属租户 = 该租户的 Agent 发现页展示。

2.2 发现页加载判定逻辑

用户打开「添加技能 / 添加工具 → 发现」页时：

① 取 POPO 租户已上架的 Skills / MCP（默认全量供给）
▶ ② 取当前 Agent 的归属租户
▶ ③ 判断该归属租户在 Studio 是否有「已上架」状态的 Skills / MCP
    · 有 → 一并加载并按 2.3 / 2.4 规则展示
    · 无（或归属租户 = POPO） → 仅展示 POPO 租户能力，与现状一致
▶ ④ 渲染发现页
判定项规则
归属租户以 Agent 的归属租户 为准（不取当前使用者所属租户）。
状态仅取归属租户在 Studio 后台「已上架」状态的 Skills / MCP；下架 / 草稿不取。
归属租户 = POPO等同现状：仅 POPO 供给一份，不重复加载。
🔑 隔离原则
易协作租户提供的技能 / 工具，只有易协作租户的 Agent 发现页才展示；非易协作租户的 Agent 不展示，避免影响其他用户。

2.3 技能（Skills）展示规则

技能复用 Studio 后台的分类与展示标签逻辑（已有逻辑，不新建一套）。租户在 Studio 后台为 Skills 指派分类标签：

  • 可指派到继承的分类标签下（见 2.3.1），发现页即混排进对应分类 Tab；
  • 也可新增分类标签（如「易协作」），发现页在现有分类 Tab 之后追加该 Tab；
  • 上述分类标签的生效范围 = 该租户下可见范围内的用户（不影响其他租户，也不改变 POPO 官方分类体系）。

2.3.1 分类标签继承规则（Studio 后台 · Skills 管理页）

其他租户的 Skills 管理页继承「网易 POPO」租户的部分分类标签，继承而来的标签不可修改；租户可在此基础上新增自有标签。

项规则
继承范围仅继承以下 4 个标签：通用、写云文档、数据分析、创建多维表格。
⚠️ POPO 租户的其他分类标签（如 HR、法务）不继承，其他租户的 Skills 管理页不可见、不可选。
不可修改继承标签不能改名、不能删除；租户管理员在「管理分类」中看到这 4 项为只读状态。
可指派继承标签可以正常给本租户 Skills 指派（这是继承的目的）；指派后该技能在发现页混排进对应 Tab。
可新增租户可新增自有分类标签（如「易协作」「工单」），新增标签可改名、可删除，仅本租户可见。
同步方式引用而非快照：POPO 租户后续调整这 4 个标签的名称时，其他租户同步生效；POPO 新增的其他标签不会自动进入继承范围（继承清单固定为上述 4 个）。
POPO 租户自身POPO 作为标签源头，其 Skills 管理页全部标签均可正常维护，不受本规则限制。
⚠️ 注意区分：「可指派的标签池」≠「发现页出现的 Tab」
本规则约束的是其他租户在 Studio 后台能选哪些分类标签。
发现页的分类 Tab 仍由已上架技能的实际分类聚合而来——POPO 官方技能默认全量供给所有租户 Agent，其中若存在 HR 分类的官方技能（如「OA助手」），则其他租户 Agent 的发现页仍会出现 HR Tab（Tab 内只有 POPO 官方技能）。
差别在于：其他租户无法把自己的技能指派进 HR / 法务，因此这两个 Tab 下不会出现该租户的技能。

为什么发现页仍有 HR / 法务
这两个 Tab 由 POPO 官方已上架技能聚合产生（官方技能全量供给所有租户 Agent），Tab 内仅有官方技能；易协作租户的技能无法进入这两个 Tab。
项规则
分类与展示标签复用 Studio 后台已有的分类 / 展示标签逻辑，由租户自行指派（可选范围见 2.3.1）。
指派到继承标签技能混排进该分类 Tab，与 POPO 官方技能同 Tab 展示（官方在前、租户在后）。
新增标签发现页在现有分类 Tab 之后追加该标签 Tab（如「法务」之后的「易协作」）。
生效范围该租户下可见范围内的用户（见第 5 节可见性），其他租户不受影响。
Tab 出现条件新增标签下存在已上架且对当前用户可见的技能时才出现；否则不出现。
说明
发现页不强制以租户名命名 Tab；归入哪个 Tab 完全由租户在 Studio 后台指派的分类标签决定——落在继承标签则混排进该 Tab，落在新增标签则新增 Tab。

2.5 重复能力

POPO 租户与归属租户各自提供了同一个能力（如两边都上架了「企查查」MCP）时：

  • 不做去重，两条都展示、各自独立。
  • 用户可分别添加；两者为不同租户供给的独立记录，配置与凭据互不影响。
3Skills 上架校验（Studio 后台）

租户在 Studio 后台点击某个 Skill 的「上架」按钮时，系统必须同时满足以下 4 项校验才允许上架；否则不上架，并弹出提醒；命中多项时提醒文案多行展示。全租户统一，无租户差异。

校验项校验条件未通过时提醒文案
① 状态Skill 状态 = 启用（原「激活」文案统一为「启用」）启用状态才可上架
② 分类标签Skill 已设置分类标签（至少 1 个）上架前请先设置分类标签
③ Skill.md 文件Skill 已上传 Skill.md 文件请先上传 Skill.md 文件
④ Skill ≠「私有」Skill 名称后的标签不为「私有」方可上架。
「私有」标签标识该 Skill 为用户自建技能（非租户官方供给），此类技能不允许上架到 AgentHub 发现页。
⚠️ 此处「私有」标签与「展示标签」是两个不同字段，不要混淆。		用户自定义技能不可上架
多项命中
若命中 2 项及以上校验，对应提醒文案按行依次展示在同一弹窗内，一次性告知租户全部待补齐项，避免反复点击。

3.1 校验 ④ 的适用范围变更

校验 ④ 原为 POPO 官方租户专属的历史规则，本次推广至全部租户，并统一提醒文案：

项调整前调整后
适用租户仅 POPO 官方租户全部租户（POPO + 其他租户）
提醒文案私有标签的技能不可上架用户自定义技能不可上架
校验项数其他租户 3 项 / POPO 4 项全租户统一 4 项
🔑 变更要点
上架校验不再有租户差异，所有租户一律 4 项；「私有」标签即用户自建技能标识，一律不可上架。
4存量数据初始化（一次性刷数据）

本次上线需通过一次性刷数据把 POPO 租户既有的上架状态迁移到统一字段「AgentHub 状态」，实现全租户交互统一。

对象初始化来源目标字段
POPO · Skills当前已在 AgentHub 技能发现页展示的 SkillsAgentHub 状态 = 已上架
POPO · MCP当前已在 AgentHub 工具发现页展示的 MCPAgentHub 状态 = 已上架
其他租户 · Skills / MCP—AgentHub 状态 = 未上架（默认）
说明
初始化只回填状态字段，不改动 Skill / MCP 本身的分类、名称标签、展示标签、可见范围与凭据。刷完后全部租户后续新增上架统一走第 3 节的 4 项校验流程（含「Skill 名称后标签 ≠ 私有」规则）。
⚠️ 存量已上架的 Skills 不因新增校验 ④ 而被强制下架；即便存量中存在带「私有」标签的已上架技能，也保持现状，校验 ④ 仅在后续新的上架动作时生效。
5可见性与定向分发
项规则
默认可见性租户在 Studio 后台上架后，默认本租户全员可见（即该租户下 Agent 的发现页均可见）。
技能定向分发复用 Skills 现有的定向分发逻辑，可在租户内进一步限定可见人群；发现页按该逻辑过滤后展示。
工具（MCP）按 Studio 已有的租户内可见 / 分发能力执行，本期不新增规则。
作用范围
（生效场景）		Skill / MCP 可见性配置仅在以下 2 处生效：
① Workflow 下技能 / 工具列表
② 工作伙伴 - 添加技能 / 添加工具 - 发现页
已绑定 Agent 后不再受可见性约束：只要用户具备该 Agent 的使用权限，即可见可用该已绑定的 Skill / MCP（Skill 与 MCP 规则一致）。
🔑 两层过滤
发现页展示 = 第一层：租户隔离（Agent 归属租户）→ 第二层：租户内可见性（默认全员可见，可复用 Skills 定向分发收敛）。
边界：可见性仅在「添加」入口过滤，绑定 Agent 后随 Agent 权限走，不做二次过滤。
6上下架与已绑定能力
Studio 后台状态发现页已绑定到 Agent 的该能力
已上架展示（按第 2 节规则）正常可用。
已下架不再展示（不可新增绑定）继续可用，不强制解绑、不自动停用。
边界
下架只影响新增绑定入口（发现页不再出现），不回溯已绑定该技能 / 工具的 Agent。

8搜索
  • 发现页搜索框搜索范围 = POPO 租户供给 + 归属租户供给，一并检索。
  • 搜索结果沿用 2.4 的顺序原则：POPO 命中结果在前，归属租户命中结果在后。
  • 搜索同样受第 3 节可见性过滤约束。
9范围与非目标

✅ 本期做

  • 发现页支持其他租户供给 Skills / MCP，按 Agent 归属租户 隔离展示。
  • 技能：复用 Studio 分类 / 展示标签逻辑，租户可将 Skills 指派到继承标签（混排进对应 Tab）或新增标签（追加新 Tab），生效范围为该租户可见范围内的用户。
  • 其他租户 Skills 管理页继承 POPO 的 4 个分类标签（通用 / 写云文档 / 数据分析 / 创建多维表格），只读不可改名删除、可指派技能；HR、法务不继承。
  • Skills 上架校验统一为 4 项，「Skill ≠ 私有」推广至全租户，文案统一为用户自定义技能不可上架。
  • 工具：混排，租户 MCP 排在 POPO MCP 之后。
  • 重复能力不去重，各自独立展示。
  • 上架后默认租户全员可见，技能复用现有定向分发逻辑。
  • 下架后发现页不再展示，已绑定继续可用。
  • 搜索覆盖两来源。

🚫 本期不做

  • 不做跨租户互通（A 租户能力供给 B 租户 Agent）。
  • 不做租户自定义分类体系（复用现有分类 / 展示标签逻辑，租户只做标签指派与新增）。
  • 不把 POPO 的全部分类标签下发给其他租户（继承清单固定为 4 个，POPO 后续新增标签不自动进入）。
  • 不因新增校验 ④ 回溯下架存量已上架技能。
  • 不做重复能力的合并 / 去重与优先级择一。
  • 不改动工具卡片样式、不新增来源标识字段。
  • 下架不回溯清理已绑定关系。
10验收标准
  1. 打开发现页时，除 POPO 租户供给外，系统按 Agent 归属租户 判断该租户在 Studio 是否有已上架的 Skills / MCP，有则一并展示。
  2. 技能：租户指派到继承标签的技能，在对应分类 Tab 内混排展示（官方在前、租户在后）；指派到新增标签的技能，在现有 Tab 之后追加该 Tab 并展示；无已上架技能则不出现该 Tab。
  3. 其他租户 Skills 管理页的分类标签中，通用 / 写云文档 / 数据分析 / 创建多维表格 为只读（不可改名、不可删除，可指派技能）；HR、法务不出现在可选范围内；租户新增的自有标签可改名、可删除。
  4. Skills 上架时全租户统一执行 4 项校验；带「私有」标签的 Skill 点击上架，提示 用户自定义技能不可上架 且不上架；命中多项校验时文案多行展示。
  5. 存量已上架技能不因新增校验 ④ 被下架。
  6. 工具：归属租户 MCP 紧随 POPO MCP 之后 混排展示。
  7. 归属租户 = POPO 或归属租户无已上架能力时，发现页表现与现状一致。
  8. 非归属租户的 Agent 看不到该租户供给（Tab 与工具均无）。
  9. POPO 与租户提供同一能力时，两条都展示，可分别添加。
  10. 租户能力上架后默认本租户全员可见；技能配置定向分发后，仅目标人群在发现页可见。
  11. Studio 后台下架某能力后，发现页不再展示，但已绑定该能力的 Agent 仍可正常使用。
  12. 发现页搜索可同时命中 POPO 与归属租户供给，且 POPO 命中在前。
