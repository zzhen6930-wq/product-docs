二共性痛点（全行业级，逐条对照各家原话）

🔴 共性 1：问题排查能力缺失 —— 所有人的痛

覆盖：6/6 业务域全部提到
业务域具体表现（各家原话）
易生活/差旅出问题不好查，没有方便的日志查询入口
费控/财务会话中工具调用参数/返回不全，排查依赖平台开发
核算/支付看不到完整调用链，知识库召回是黑盒，误召回难定位
资金不知道回答准不准，卡片内容不展示，调用过程不可见
Echo用户侧和 Echo 侧都看不到中间过程，只能找平台开发查日志
数据只有输入输出，效果差不知道差在哪，完全黑盒
本质：平台只给了最终结果，中间过程（用了哪个工具、传了什么参数、返回什么、花多久、哪报错）完全不透明。业务方处于「盲人摸象」，出问题只能找平台开发，效率极低。

🔴 共性 2：Skill 可观测性 / 治理缺失 —— 迭代没数据支撑

覆盖：5/6（数据为间接提及，其余均明确提出）
业务域具体表现
易生活/差旅Skill 发上去后效果完全不知道，没有数据反馈
费控/财务Skill 唤起是否准确、执行是否成功，没有量化数据
核算/支付Skill 调用量、准确率、耗时分布都没有，业务方被问住
资金改完提示词/Skill 后，无法量化评估效果变化
EchoSkill 迭代后效果变好变差不知道，成功率/执行率/耗时全无
本质：Skill 是 Agent 的核心能力单元，但平台完全没有围绕 Skill 生命周期的治理（版本、监控、灰度、观测）。业务方改完心里没底，全靠感觉。

🔴 共性 3：评测体系缺失 —— 改完不知道是好是坏

覆盖：4/6 明确提出，其余 2 个有隐含需求
业务域具体表现
核算/支付改一处坏一处，没有回归测试，提示词几百行改完没底
资金没有评估手段，测试集构建困难，人工覆盖不全
EchoAgent 效果无法评估，提示词改动效果全靠感觉
数据报表生成质量靠人眼判断，没有客观标准
本质：缺少标准化的 Agent 评估框架。业务方无法量化「效果提升了多少」，也就无法判断投入产出。

🔴 共性 4：Prompt 版本管理缺失

覆盖：3/6 明确提及，其余隐含
业务域具体表现
易生活/差旅版本全靠线下管理，容易搞乱，无法回退
费控/财务提示词 300+ 行，越来越长，没有版本概念

本质：Skill 已经有版本了，但 Prompt 作为改动最频繁的资产，反而没有版本管理。

🟡 共性 5：服务稳定性 & 被动响应

覆盖：3/6 明确提及

五三个关键判断（精简）

1. 可观测性是最短的那块板。6 个业务域全部把「看不到中间过程、出问题没法查」列为核心痛点，是平台级基础缺失。没有它，评测、灰度、治理都无从谈起——这是 P0 中的 P0。

2. 不同场景对平台的要求分化严重。问答类要知识库/多 Agent/控权；工具类要 Skill 治理/工程化；数据类要准确性/确定性/可视化；代码类要指令遵循/执行环境。平台不能「一套方案打所有场景」，需分层设计。

3. 高准确性场景出现「反 Agent 化」信号，值得警惕。资金侧明确提出纯 Agent 不适合高准确性场景，想要 Workflow 固化流程，或「AI 解析参数 + 固定工具查询 + 审核 Agent 核实数据准确性」的混合架构。平台需思考：除了纯 Agent，是否要提供 Workflow / 固定流程模式，给业务方选择余地。
