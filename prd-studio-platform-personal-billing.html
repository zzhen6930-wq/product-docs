01 背景与目标

由超管集中提供可用模型，降低租户重复接入的成本，同时保障每个租户的模型配置能够独立编辑。

仅超管后台可批量新建或复制模型给租户；每个目标租户获得独立的一套模型配置。

这不是多个租户共用同一配置，也不由网易POPO租户自动分发。复制完成后，来源与副本之间没有持续更新关系。

租户直接选用已分配的模型配置。个人计费默认使用提问人额度，Agent 可改为使用创建人额度；应用计费扣除申请的应用账号额度。直接使用不代表免登录、免计费或不受额度约束。

术语定义
超管后台唯一跨租户模型创建与复制入口。
网易POPO租户普通租户管理入口，只管理本租户模型，不向其他租户共享。
模型副本复制时按来源配置初始化，具有独立模型ID与归属租户；后续可独立修改。
全部租户本次操作时 Studio 当前全部租户；不是持续订阅关系。
指定租户本次创建或复制所选的目标租户，支持多选。
模型使用入口WorkHub、AgentHub，可多选，至少选一个。
个人计费Agent 选择使用提问人额度或使用创建人额度。
应用计费使用模型所配置的应用账号额度。

范围覆盖超管新建、编辑、另存、复制、列表筛选，租户模型管理和 Agent 额度承担人选择。不包含跨副本持续同步、自动替换已有 Agent 绑定或调整底层 Token 结算规则。

03 核心产品链路

  1. 超管进入模型管理，新建模型并配置调用参数；主动选择全部租户或指定租户，并勾选模型使用入口。
  2. 保存后系统为每个目标租户创建一条独立模型配置；列表每行对应一个模型ID和归属租户。
  3. 需要向更多租户提供同类模型时，从操作栏点击“复制”，选择租户范围和使用入口，生成新的独立副本。
  4. 后续编辑只修改当前记录；归属租户可单选变更，不联动来源或其他租户的副本。
  5. Agent 选用本租户可用模型，并按已保存的个人或应用额度规则执行调用。

示例：向 A、B 复制模型 M 后生成 M-A、M-B 两条独立记录，初始参数相同。修改 M-A 的名称、协议或参数，不改变 M-B，也不回写来源 M。

04 模型复制与配置独立性

4.1 数据和权限边界

  • 只有超管可创建跨租户模型或发起复制；普通租户（含网易POPO）不能通过页面或接口提交其他租户范围。
  • 每个目标租户单独新建模型配置并分配独立ID；模型名称、标识、接口协议、调用参数、计费类型等复制时一致，后续不共享可变配置。
  • 复制不复制 Agent 绑定、不迁移用户额度、不修改来源记录，也不覆盖目标租户的既有模型。名称相同不代表同一条配置。
  • 复制时“模型使用入口”以弹窗本次勾选值为准，不继承来源入口。
  • 凭据由服务端按既有安全机制处理，不回显；跨租户账号有效性、部门 / 人员 / Bot 的可用性需联调确认。

4.2 生命周期

事件行为
来源模型被编辑、停用或删除不自动修改已经生成的副本。
编辑某租户副本只影响当前模型记录及其关联调用。
新建或复制选择全部租户为执行时当前所有租户分别创建；未来新增租户不自动继承本次复制。
编辑归属租户对当前记录单选新归属，不生成多份配置；涉及已有 Agent 绑定时的处理需评审。
再次复制到已有相似模型的租户按当前原型新增独立记录，不覆盖已有配置。
单次请求重试生产应按操作ID保证幂等，避免一次确认因重试重复创建；用户主动再次确认复制属于新操作。

批量创建部分失败的结果提示和重试方式为生产联调项，不能将部分成功显示为全部成功。原“网易POPO共享、源更新同步、共享范围撤回”的方案已被独立复制方案替代。

5.3 查看绑定Agent

点击“查看绑定Agent”打开弹窗，不能跳转 Agent 配置、选中模型或新建绑定。停用模型仍可查看绑定情况。

  • 标题：模型「模型名称」绑定的 Agent。
  • 字段仅包括 Agent 名称、Agent ID。来自真实绑定数据，只展示当前空间、当前用户有权查看的 Agent。
  • 无绑定时展示“暂无 Agent 使用该模型”。不展示“当前为原型示例数据”文案。
  • 弹窗参考当前原型：最大宽度 720px，紧凑标题与表格；窄屏适配，Agent ID 可完整查看。支持右上角关闭、底部关闭与 Esc。

空间自建无记录时展示新建引导；筛选结果为空时展示未找到匹配模型，不将其误判为尚未创建模型。

06 空间自建模型

空间自建用于补充专属接入或应用账号计费需求。新建操作进入独立页面，包含“01 基本信息”和“02 接入配置”，不使用新建弹窗。网易POPO及其他普通租户均不展示“03 模型共享”，不支持跨租户分发。

分组字段规则
基本信息模型名称必填，去除首尾空格后不能为空；原型长度上限 60。
基本信息模型标识必填；原型长度上限 100。
基本信息标签（逗号分隔）选填。
接入配置凭据方式共享 Key / 个人 Key，默认共享 Key；与计费方式是不同维度。
接入配置共享 Key共享 Key 模式显示密码输入；保存后不回显。具体必填条件沿用接入协议。
接入配置接入方个人 Key 模式展示；按用户身份提供凭据，候选与校验沿用现有能力。
接入配置接口协议（Provider）必填，默认 OpenAI 兼容；原型还包含 deepseek、anthropic、custom。
接入配置模型 API 地址必填，校验 URL。
接入配置计费方式个人计费 / 应用计费，原型默认个人计费；对应账号须实际支持选定方式。

个人计费下方展示“扣除提问人Token额度”；应用计费下方展示“扣除申请的应用账号额度”。修改选项立即更新说明。

保存成功返回空间自建列表并显示新模型；取消、返回不保存当前修改。编辑复用同一页面。底部保留“凭据保存后不回显”提示。

凭据方式不能推导计费方式：共享 Key 不必然等于应用计费，个人计费也不要求租户手动填写个人 Key。最终可选组合及账号验证应由现有接入能力约束，不能仅凭前端枚举决定实际扣费主体。

租户侧创建的模型归属当前租户。取消原“应用计费自动指定网易POPO并置灰”的交互，因为租户页面已不存在共享范围字段；任何计费类型都不能从此入口跨租户创建。

07 Agent 配置与计费链路

7.1 页面展示与交互

位置：Agent 管理 → Agent 详情页 → 模型设置。模型下拉按“平台提供”“空间自建”分组，选项为“模型名称 · 计费方式”。“计费方式”字段与模型字段并排，不使用前台大卡片、独立大面积高亮或额外选择区。

所选模型类型计费方式字段下方提示
个人计费（含平台和空间自建）普通单选下拉框：使用提问人额度、使用创建人额度。默认使用提问人额度。提问人：扣除提问人的 Token 额度
创建人：扣除此 Agent 创建人的 Token 额度
应用计费沿用只读“应用计费”展示，不展示个人额度选择。扣除申请的应用账号额度

7.2 默认值、保存和回显

  • 首次选择一个人计费模型，默认“使用提问人额度”。模型的个人 / 应用计费类型由模型配置决定，Agent 页面仅选择个人计费情况下的额度承担人。
  • 下拉选择立即更新提示，并将 Agent 标记为“配置未保存”；不立即更改线上绑定或发生扣费。点击“保存配置”后，模型绑定和额度承担方式一并保存。
  • 重新进入已保存配置时回显保存值。原型仅在当前演示会话内保留数据；正式产品须持久化。
  • 切换到另一个未保存过的个人计费模型时恢复默认提问人；切回当前已保存绑定的模型时回显其已保存额度承担方式。保存到新模型后以新绑定为准。
  • 切换为应用计费时隐藏个人额度选项，保存不携带有效个人额度承担配置；继续使用该模型绑定的应用账号。
  • 修改只影响当前 Agent，不改写模型定义，也不批量改变其他 Agent 的额度承担配置。

7.3 费用归属

配置实际扣费主体说明
使用提问人额度当前调用的实际提问人不同提问人分别使用自己的 Token 额度。
使用创建人额度此 Agent 的创建人所有提问统一使用创建人额度；“创建人”不是当前登录编辑者，也不是模型创建人或平台管理员。
应用计费模型配置对应的应用账号沿用当前逻辑；不因个人额度充足而自动改扣个人。

个人额度承担方式应存储在 Agent 配置层，由服务端读取 Agent 创建人身份和调用人身份确定账户，不能由请求随意指定其他用户。身份无法识别或相应额度不可用时按现有服务明确返回失败，不自动改扣另一方或应用账号。

本期不改变 Token 单价、扣减计算或失败请求的底层结算规则。创建人离职、停用或 Agent 所有权转移的处理尚未确认，需评审后明确，不能用当前编辑人自动替代创建人。

08 超管后台 · 模型管理

8.1 入口与通用字段

入口：平台管理（超管后台）→ 能力管理 → 模型。保留“模型列表 / 接入方”Tab，以及新建、编辑、另存、删除，操作栏新增“复制”。

表单保留“01 基本信息”“02 接入配置”“03 展示设置”“04 可见性规则”。模型名称、标识、接口协议和API地址按原规则校验。“模型参数 · 高级配置”默认折叠，仅保留模型参数 JSON，不含组织归属或模型候选入口；JSON必须为合法对象。

8.2 新建：05 使用范围

字段规则
使用范围必填，默认空，显示“请选择”；选项为全部租户、指定租户。未选择阻止保存并提示“请选择使用范围”。
指定租户使用范围为指定租户时动态展示；候选为Studio当前所有租户，支持搜索、多选；至少选1个。
模型使用入口必填；WorkHub、AgentHub多选，默认均不勾选；未选提示“请至少选择一个模型使用入口”。

保存时按目标租户逐一新建独立配置。例如选 A、B、C 后新增3条模型记录，每条有独立ID与参数对象。只在创建时应用所填配置，不建立后续联动。

8.3 编辑：单条租户配置

从某一行“编辑”进入，“05 使用范围”不展示全部 / 指定租户范围选择，改为必填的“归属租户”单选，回显当前租户。下拉支持名称搜索，当前选择以蓝色高亮和勾选标识显示；选中另一租户后替换原选择并收起，不能多选。

模型使用入口回显当前记录已保存值，可修改且至少保留一个。保存提示“仅修改当前租户的模型配置，不影响其他租户副本”。取消不保存。修改当前配置不能联动来源或其他副本。

8.4 复制模型给其他租户

点击列表“复制”打开弹窗，标题固定为复制模型给其他租户。不显示来源模型名称、来源租户或“来源模型：……”文案。

字段默认值与交互
复制租户范围全部租户 / 指定租户；当前原型默认全部租户。此默认与新建页使用范围默认空不同。
指定租户选指定租户时动态展示，候选包含Studio当前全部租户，支持搜索多选，至少选1个；搜索不清除已选值。
模型使用入口WorkHub、AgentHub，支持多选，必填。每次打开均置空，不继承来源配置，也不保留上次勾选。

底部为“取消”“确认复制”。无目标租户或无模型使用入口时阻止确认，分别提示“请选择至少一个租户”“请至少选择一个模型使用入口”。选定入口后再次打开弹窗，仍必须重新选择。

确认后为每个目标租户新增独立副本，采用本次入口选择；弹窗关闭，列表刷新并提示成功数量。不覆盖目标租户已有模型；来源及已有副本不变。全部租户当前包含来源租户，显式选择来源租户也会新增独立记录；去除来源或同名去重策略如需调整应另行确认。

8.5 列表与筛选

项目要求
字段模型配置、归属租户、接入方式 / 接入方、接口协议、展示、计费方式、标签、状态、操作。
归属租户每行一个租户，一行就是一条独立模型记录。
计费方式原员工额度改为个人额度；应用额度不变。
筛选名称、Provider、状态、接入方、归属租户；归属租户支持搜索、多选，所选租户取并集，与其他条件取交集。
操作编辑、另存、复制、删除。另存复用新建表单，使用范围需重新选择；复制使用专门弹窗。
删除原型仅删除当前记录，其他副本不变；存在Agent绑定时的阻止或失效规则需评审。

原型仍使用本地示例租户和内存模型数据，刷新后恢复。真实目录、鉴权、凭据处理及跨后台租户视图需服务端实现，不能将前端演示视为真实复制成功。

09 权限与原型待收敛项

事项规则 / 待确认
跨租户操作仅超管可新建、复制或修改模型归属，租户侧无共享入口。服务端需校验角色与目标租户。
配置独立已复制模型可以独立编辑；租户侧具体编辑权限沿用现有权限体系，不代表可以修改其他租户。
归属变更若模型已有Agent绑定，转移归属时是否阻止、解绑或置失效需确认；不能暴露原租户绑定数据。
凭据与可见性源账号、部门、人员、Bot是否在目标租户有效，需明确校验和映射；复制配置不等于复制账号授权。
历史记录历史共享配置迁移为独立记录的ID、绑定保留及来源追溯需要迁移方案，禁止按名称自动合并。
应用模型供给超管列表已有应用额度模型；其租户端目录分类与账号可用性需联调，不能把租户“平台提供”示例分类误当成超管功能限制。

AC-09编辑独立性编辑任一模型名称、参数或归属，只更新该记录，不改变来源或其他副本。
AC-10编辑入口回显并保存当前模型使用入口，至少保留一项。
AC-11复制入口每行显示复制按钮，打开复制模型给其他租户弹窗。
AC-12复制文案不出现来源模型名称/来源租户说明。
AC-13复制默认范围默认全部租户，模型使用入口默认全部不勾选；再次打开仍清空入口。
AC-14复制指定租户支持搜索多选、保留搜索前勾选；空选阻止确认。
AC-15复制入口校验WorkHub/AgentHub至少一项；无值阻止确认。
AC-16复制结果每目标租户生成独立副本，入口采用弹窗选择，不覆盖既有模型。
AC-17副本独立性更改来源、任一副本的参数、入口或状态，其他副本保持不变。
AC-18取消与重试取消不产生记录；生产同次操作重试幂等，主动再次复制按新操作处理。
AC-19列表字段归属租户每行单一值，员工额度改为个人额度，应用额度不变。
AC-20归属筛选支持多选并集，与其他筛选交集，清空恢复全部记录。
AC-21高级配置默认折叠仅含模型参数JSON，无组织归属或候选入口；非法JSON展开并提示。
AC-22另存与删除另存不修改原记录，范围需主动选择；删除仅当前记录，其他副本不变。
AC-23双Tab租户侧保留平台提供/空间自建；仅自建提供计费方式筛选。
AC-24绑定弹窗查看绑定Agent展示名称和ID，不改选模型，不创建绑定。
AC-25租户表单必填、URL校验、保存返回列表、取消不保存正常。
AC-26个人计费UI计费方式与模型并排，紧凑下拉含提问人/创建人，默认提问人。
AC-27个人计费保存变更标记未保存，保存后回显，其他Agent不变。
AC-28提问人额度按实际调用人分别扣额度。
AC-29创建人额度统一扣当前Agent创建人，不扣当前编辑者或模型维护人。
AC-30应用计费隐藏个人选择，提示扣除申请的应用账号额度，保存逻辑不变。
AC-31模型切换新选个人模型默认提问人，切回已保存模型回显保存值；应用无个人承担选项。
AC-32失败处理身份或额度不可用时明确失败，不自动跨主体或计费类型兜底。
AC-33角色校验非超管不能通过参数构造调用跨租户新建/复制。
AC-34目录异常候选加载失败可重试，保存时校验租户有效性，不扩大目标范围。

11 评审决策与上线观察

需确认：已有绑定模型的归属变更 / 删除策略、跨租户凭据和可见性资源校验、批量复制部分失败处理、相同模型重复复制策略，以及历史共享记录迁移为独立副本的方案。

先实现超管权限、单条模型持久化和批量复制，再联调租户端目录、Agent绑定和计费。生产观察批量创建成功率、失败租户明细、错误覆盖或跨副本联动、计费主体异常。
