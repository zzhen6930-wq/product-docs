PRODUCT REQUIREMENTS · V1.1

平台个人计费模型
供给与同步

网易POPO统一维护，租户直接使用，费用归属实际提问人。

2026-10-27状态：评审稿依据：当前模型管理原型

01 背景与目标

租户使用通用模型时，若仍需自行申请模型账号、填写接入信息，再为 Agent 配置模型，会增加首次使用成本，也会造成多租户重复维护同一批模型。

平台将网易POPO租户下的个人计费模型，按每个模型配置的共享范围提供给目标租户，并持续同步更新。

租户进入“平台提供”即可查看，在 Agent 配置中直接选择使用，无需为这批模型另建模型配置或申请应用账号。实际调用扣除提问人的 Token 额度。

“直接使用”指免去租户侧模型接入配置，不代表免计费、免登录或无额度限制。模型是否可调用仍取决于其可用状态及提问人的身份、额度。

目标用户结果
降低接入门槛新租户无需手工导入其获授权的平台模型，即可配置 Agent。
平台统一维护网易POPO源模型新增、配置更新、共享范围和可用状态变化能够传递至获授权租户。
费用归属清晰平台模型固定为个人计费；空间自建模型按配置支持个人计费、应用计费。

02 术语与需求范围

术语定义
网易POPO租户平台模型的来源租户；其个人计费模型是平台供给的源数据。
目标租户接收平台供给的业务租户。目标租户由模型的“全部租户 / 指定租户”共享范围确定，接收方无需手工添加。
平台提供源自网易POPO租户的个人计费模型目录；不能混入应用计费模型。
空间自建当前空间自行配置的模型，维持现有空间隔离边界，不反向同步到网易POPO或其他租户。
个人计费扣除提问人Token额度。
应用计费扣除申请的应用账号额度。

本期范围：平台模型供给与更新、双 Tab 模型列表、空间自建模型表单、查看绑定 Agent、Agent 模型与计费方式展示。

范围外：调整 Token 单价、充值与账单能力、跨租户共享自建模型，以及自动将已有 Agent 迁移至其他模型。

本文按“供给覆盖租户、使用入口位于空间”描述。租户内各空间的授权范围需沿用现有权限体系；如现有产品存在空间白名单，应在评审时确认适用范围。

→
3 · 租户使用平台提供 Tab
Agent 直接选用
→
4 · 实际计费识别实际提问人
扣除其 Token 额度
  1. 平台在网易POPO租户维护个人计费模型，无需为各目标租户重复创建配置。
  2. 系统将符合条件的模型纳入平台目录，并按共享范围向已有租户和新租户提供。
  3. 租户管理员查看“平台提供”，可查看当前空间有哪些 Agent 绑定该模型。
  4. 在 Agent 管理详情页选择模型，系统展示“个人计费”和“扣除提问人Token额度”；保存后建立绑定。
  5. 用户向该 Agent 提问时，系统按实际提问人识别个人额度，不能将源租户、Agent 创建人或应用账号作为默认扣费主体。

示例：网易POPO新增一个个人计费模型并设为“全部租户”后，租户甲、租户乙无需新建模型即可选用；若设为“指定租户”且只选甲，则乙不可见、不可选用。甲租户内小王向 Agent 提问，扣除小王的 Token 额度；小李提问则扣除小李的 Token 额度。

04 平台供给与同步规则

4.1 同步范围与归属

平台提供的个人计费模型：默认扣除提问人额度，不支持修改。

该规则随平台模型生效，不提供扣费规则编辑入口；不能改为扣除应用账号、Agent 创建人或其他用户额度。在租户模型管理、Agent 配置及接口提交中均不可覆盖该规则。此约束仅针对平台提供模型，空间自建模型仍按自身计费配置处理。

  • 供给条件为“源租户是网易POPO”且“计费方式是个人计费”。进入个人计费供给池后，还需按模型共享范围判断目标租户是否获授权，不能在页面写死模型清单。
  • 网易POPO租户下的应用计费模型不进入平台供给目录。其他租户的个人计费模型也不因此自动成为平台模型。
  • 模型名称、标识、接入方式 / 接入方、接口协议、标签、源状态及调用所需配置随源模型更新；平台模型的计费方式固定展示“个人计费”；其扣费规则默认为“扣除提问人额度”，不支持修改。
  • 系统应使用稳定的源模型身份关联平台目录与 Agent 绑定，不能仅按展示名称或模型标识去重。名称相同的自建模型与平台模型分别存在。
  • 同步的是模型使用能力和必要元数据；凭据由服务端安全使用，不向目标租户回显或要求其重新填写。

4.3 模型共享范围

本次新增：网易POPO租户在新建模型页配置模型共享对象。平台不再默认将每个源模型无条件提供给所有租户；模型是否进入某租户的平台目录，由个人计费条件与共享范围共同决定。

目标租户可见 = 网易POPO源模型 ∩ 个人计费 ∩ 共享范围包含该租户

实际调用还需满足模型启用状态、当前用户权限及额度条件。共享范围不改变计费方式与扣费主体。

配置 / 变化产品行为
全部租户覆盖 Studio 当前所有租户，并自动包含后续新增租户；不保存为当前租户 ID 的静态快照。
指定租户仅向勾选的租户提供；未选择的租户不展示该模型，也不能新绑定或调用。后续新建租户不会自动加入。
增加指定租户保存后为新增对象同步模型；已授权对象继续获得最新配置。
移除租户 / 全部改指定保存后撤回范围外租户的供给与调用权限，不改扣其他账号、不自动替换模型。既有 Agent 绑定失效展示、通知和在途请求处理需评审确认。
指定改全部保存后扩展至所有租户，并覆盖未来新增租户。

租户授权须在服务端判断，不能仅靠隐藏列表控制调用权限；同步重试时应用共享范围的最新版本，防止已撤回的租户因旧事件恢复授权。

继续沿用此前“平台仅提供个人计费模型”的约束：网易POPO应用计费模型也可录入共享配置，但本期不会因此进入平台个人计费目录。应用计费模型是否另行共享不在本次需求内，需另行确认。

4.4 一致性要求

同步需可重试、可补偿，重复事件不产生重复记录；过期更新不能覆盖较新配置。单租户同步失败不应阻断其他租户。列表“刷新”用于重新获取数据，不应成为后台同步的唯一触发方式。

新增 / 更新的同步时效、失败告警与补偿周期尚未约定，列入评审项。源端停用或撤回后的调用校验不能仅依赖旧页面状态，以免前端仍展示可用时继续发起无效调用。

5.3 查看绑定Agent

点击“查看绑定Agent”打开弹窗，不能跳转 Agent 配置、选中模型或新建绑定。停用模型仍可查看绑定情况。

  • 标题：模型「模型名称」绑定的 Agent。
  • 字段仅包括 Agent 名称、Agent ID。来自真实绑定数据，只展示当前空间、当前用户有权查看的 Agent。
  • 无绑定时展示“暂无 Agent 使用该模型”。不展示“当前为原型示例数据”文案。
  • 弹窗参考当前原型：最大宽度 720px，紧凑标题与表格；窄屏适配，Agent ID 可完整查看。支持右上角关闭、底部关闭与 Esc。

空间自建无记录时展示新建引导；筛选结果为空时展示未找到匹配模型，不将其误判为尚未创建模型。

06 空间自建模型

空间自建用于补充专属接入或应用账号计费需求。新建操作进入独立页面，包含“01 基本信息”和“02 接入配置”，不使用新建弹窗。网易POPO租户额外展示“03 模型共享”，普通租户不展示。

分组字段规则
基本信息模型名称必填，去除首尾空格后不能为空；原型长度上限 60。
基本信息模型标识必填；原型长度上限 100。
基本信息标签（逗号分隔）选填。
接入配置凭据方式共享 Key / 个人 Key，默认共享 Key；与计费方式是不同维度。
接入配置共享 Key共享 Key 模式显示密码输入；保存后不回显。具体必填条件沿用接入协议。
接入配置接入方个人 Key 模式展示；按用户身份提供凭据，候选与校验沿用现有能力。
接入配置接口协议（Provider）必填，默认 OpenAI 兼容；原型还包含 deepseek、anthropic、custom。
接入配置模型 API 地址必填，校验 URL。
接入配置计费方式个人计费 / 应用计费，原型默认个人计费；对应账号须实际支持选定方式。

个人计费下方展示“扣除提问人Token额度”；应用计费下方展示“扣除申请的应用账号额度”。修改选项立即更新说明。

保存成功返回空间自建列表并显示新模型；取消、返回不保存当前修改。编辑复用同一页面。底部保留“凭据保存后不回显”提示。

凭据方式不能推导计费方式：共享 Key 不必然等于应用计费，个人计费也不要求租户手动填写个人 Key。最终可选组合及账号验证应由现有接入能力约束，不能仅凭前端枚举决定实际扣费主体。

6.1 新增“03 模型共享”

仅网易POPO租户展示，位置在“02 接入配置”下方、保存操作区上方；编辑模型时回显已保存的共享范围及指定租户。

字段枚举 / 数据来源交互与校验
共享范围全部租户、指定租户必填。原型默认“全部租户”，以延续原先默认全量供给的行为。
指定租户Studio 当前全部租户，包含网易POPO；以稳定租户 ID 保存，名称用于展示仅当共享范围为“指定租户”时动态展示，使用下拉多选样式：顶部搜索框、单列复选项、已选行灰底高亮与蓝色勾选；收起后显示已选租户名称。支持名称搜索，至少选择 1 个租户。
  • 切换为“指定租户”即时显示多选控件，搜索不清除已选项，并显示已选数量。
  • 切换为“全部租户”隐藏指定租户字段且不校验该字段；保存时不提交过期指定列表。当前未保存表单内切回“指定租户”保留先前勾选，方便调整。
  • 保存时服务端重新校验租户 ID 存在且可用；租户已删除、列表加载失败等情况应提示并允许重试，不能将失败误作“全部租户”。
  • 新建或编辑保存成功后共享配置生效并触发供给更新；取消不改变已保存配置。
  • 普通租户的新建 / 编辑页面不显示共享模块，也不能通过提交共享字段获得平台供给权限。

当前单文件原型新增顶部租户切换，用于演示网易POPO的配置与接收租户的可见差异。租户选项为本地模拟目录；生产需接入 Studio 完整租户数据，支持加载完整候选，不能只列出前端写死的租户或首屏数据。

07 Agent 配置与计费链路

Agent 管理详情页的模型下拉按“平台提供”“空间自建”分组，展示可用模型。选项文案为“模型名称 · 计费方式”。选择后需保存配置才形成有效绑定。

模型选择计费方式字段字段下方文案
平台提供的任一模型个人计费扣除提问人Token额度
空间自建个人计费模型个人计费扣除提问人Token额度
空间自建应用计费模型应用计费扣除申请的应用账号额度
  • “扣费规则”字段统一改名为“计费方式”，为模型配置的只读结果，不允许在 Agent 页面单独改写。平台提供的个人计费模型默认按“扣除提问人额度”执行且不支持修改；现有提示文案“扣除提问人Token额度”表达同一规则。
  • 切换模型即时更新枚举值、提示和来源；不因选择模型立即发生费用。
  • 平台模型无需租户补录应用账号。调用时由现有身份与计费链路识别提问人。
  • 个人计费不能扣到 Agent 创建人、模型维护人或网易POPO源租户的应用账号；应用计费不能因个人额度充足而改扣个人。
  • 身份无法识别、个人额度不足或应用额度不可用时，按现有服务返回明确失败原因；不得静默跨计费方式兜底。
  • 建议：已绑定模型失效时保留失效提示，要求管理员明确选择替代模型并保存，避免原型中自动选择第一个可用模型的演示行为进入生产。

本期不改变额度扣减计算、失败请求是否计费等底层结算规则，复用现有计费服务；该服务需要支持并验证上述费用归属。

08 权限与原型待收敛项

当前 HTML 是交互原型，使用内存示例数据；未实现后台同步、真实鉴权、凭据保存和实际扣费。页面可交互不能视为这些能力已实现。

事项当前原型PRD 建议 / 待确认
平台模型编辑 / 删除平台行与自建行均展示编辑、删除，使用相同本地修改逻辑。与“源端统一同步”存在冲突。建议平台源字段仅由网易POPO授权管理员维护；目标租户隐藏或禁用编辑、删除。是否保留本地覆盖需产品确认。
平台模型启用 / 停用原型仅修改本地状态，无作用域。建议租户侧操作只控制本租户或当前空间的可用性，不修改源模型、不影响其他租户；具体作用域需确认。源停用优先于本地启用。
平台同步与本地设置原型没有版本或同步状态。如允许本地停用，建议与源状态分开保存，源更新不重置本地选择；平台配置仍以源端为准。
租户 / 空间可见范围原型仅模拟当前空间。租户可见范围按共享配置判定；租户内空间可见与操作范围需结合现有角色权限确认。
绑定模型被删除原型可删除并自动改选其他模型。建议阻止删除仍被绑定的自建模型，先展示绑定并要求解除；平台撤回按失效处理，不静默迁移。
计费方式修改原型允许直接修改。建议修改已绑定自建模型的计费方式前提示影响；是否需要重新确认发布，纳入评审。
以上建议尚未修改当前交互原型。评审必须明确平台行操作的最终权限，不能将目标租户对平台模型的本地修改反向写入网易POPO。

09 验收标准

编号场景预期结果
AC-01网易POPO存在个人计费与应用计费模型只有个人计费模型进入供给池；当前租户只看到共享范围包含自己的模型，且不漏项。

AC-05切换两个 Tab平台无计费方式筛选；自建可按两种计费方式筛选，切换时重置筛选。
AC-06查看绑定Agent只弹窗，显示名称与 ID；不改变模型选择或绑定，不泄露其他空间绑定。
AC-07新建空间模型进入独立页面；校验必填与 URL；保存后出现在自建列表。
AC-08切换模型表单的计费方式正确显示两条指定提示文案。
AC-09Agent 选择平台 / 自建模型计费方式与提示正确联动；保存前不建立新绑定。
AC-10两个不同用户调用同一个个人计费 Agent分别扣除实际提问人的 Token 额度，不能都扣到创建人或应用账号。
AC-11调用应用计费模型扣除对应申请的应用账号额度。
AC-12个人额度不足或身份识别失败明确失败；不自动切换应用计费账号。
AC-13同步失败、重试或乱序更新可补偿，无重复模型，不回退至旧配置；按评审确定的时效验收。
AC-14源模型停用 / 删除 / 改为应用计费不继续提供失效的个人计费能力，不静默更改绑定和扣费主体；按确认后的失效交互验收。
AC-15平台模型与自建模型标识相同独立显示与绑定，平台更新不覆盖自建模型。
AC-16租户操作平台模型操作权限符合第 8 节最终评审结果，不影响其他租户或源配置。
AC-17网易POPO新建模型显示“03 模型共享”；共享范围可选全部租户、指定租户，普通租户不展示。
AC-18切换至指定租户动态展示 Studio 全部当前租户的多选；支持搜索、多选、取消选择；空选阻止保存。
AC-19保存后重新编辑回显共享范围与所选租户；取消修改不影响原配置。
AC-20全量与定向供给全部租户自动覆盖后续新增租户；指定租户仅覆盖已勾选对象，目录与 Agent 选项保持一致。
AC-21缩小共享范围范围外租户不能新绑定或调用；不静默切换模型或计费方式；旧同步事件不得重新授权。
AC-22租户数据异常候选加载失败可重试；已删除租户保存时被识别，不扩大共享范围。
AC-23平台个人计费模型的扣费规则默认且固定为“扣除提问人额度”；模型管理与 Agent 配置均无可修改入口，服务端拒绝覆盖扣费规则的提交。空间自建模型的计费配置不受此限制影响。

10 评审决策与上线观察

需收敛的决策

  1. 共享范围收缩时，既有 Agent 的失效展示、管理员通知和在途请求处理；历史未配置共享范围的源模型建议按“全部租户”迁移，需上线前确认。
  2. 平台行“编辑、删除”是否仅对源租户管理员开放；租户侧停用究竟作用于整个租户还是当前空间。
  3. 源停用、删除、计费方式变化的失效展示、已有 Agent 调用行为与恢复规则。
  4. 同步时效目标、失败补偿周期，以及新租户初始化完成条件。
  5. 个人身份到额度账号的映射范围；用户跨租户使用时沿用的额度归属规则。
  6. 空间自建已绑定模型的删除限制与计费方式变更确认机制。

上线顺序建议

先完成源目录识别与身份计费验证，再按共享范围初始化已有租户目录，接入持续同步与新租户初始化，最后开放前端双 Tab 与 Agent 选用。已有自建模型和 Agent 绑定保持原状，不能仅凭模型同名自动迁移至平台目录。

上线后观察

关注平台目录覆盖率、同步成功率与延迟、首次绑定平台模型的耗时、调用成功率，以及个人计费归属异常。具体阈值在研发评审时确定，不以原型示例数量作为上线目标。

依据：本轮已确认需求与 模型与计费交互原型。文档中的“建议 / 待确认”为同步与权限边界的补充设计，不表示已获确认。
