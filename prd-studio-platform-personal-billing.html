01 背景与目标

租户使用通用模型时，若仍需自行申请模型账号、填写接入信息，再为 Agent 配置模型，会增加首次使用成本，也会造成多租户重复维护同一批模型。

平台将网易POPO租户下的个人计费模型，按每个模型配置的共享范围提供给目标租户，并持续同步更新。

租户进入“平台提供”即可查看，在 Agent 配置中直接选择使用，无需为这批模型另建模型配置或申请应用账号。个人计费默认扣除提问人的 Token 额度，也可在 Agent 配置中选择使用创建人额度。

“直接使用”指免去租户侧模型接入配置，不代表免计费、免登录或无额度限制。模型是否可调用仍取决于其可用状态及实际额度承担人的身份、额度。

目标用户结果
降低接入门槛新租户无需手工导入其获授权的平台模型，即可配置 Agent。
平台统一维护网易POPO源模型新增、配置更新、共享范围和可用状态变化能够传递至获授权租户。
费用归属清晰平台模型固定为个人计费；空间自建模型按配置支持个人计费、应用计费。

02 术语与需求范围

术语定义
网易POPO租户平台模型的来源租户；其个人计费模型是平台供给的源数据。
目标租户接收平台供给的业务租户。目标租户由模型的“全部租户 / 指定租户”共享范围确定，接收方无需手工添加。
平台提供源自网易POPO租户的个人计费模型目录；不能混入应用计费模型。
空间自建当前空间自行配置的模型，维持现有空间隔离边界，不反向同步到网易POPO或其他租户。
个人计费使用个人 Token 额度；Agent 默认使用提问人额度，可选择使用该 Agent 创建人额度。
应用计费扣除申请的应用账号额度。

本期范围：平台模型供给与更新、租户侧双 Tab 模型列表、空间自建模型表单、查看绑定 Agent、超管后台模型管理与按租户分发、Agent 模型与额度承担人配置。

范围外：调整 Token 单价、充值与账单能力、跨租户共享自建模型，以及自动将已有 Agent 迁移至其他模型。

本文按“供给覆盖租户、使用入口位于空间”描述。租户内各空间的授权范围需沿用现有权限体系；如现有产品存在空间白名单，应在评审时确认适用范围。

  1. 平台在网易POPO租户维护个人计费模型，无需为各目标租户重复创建配置。
  2. 系统将符合条件的模型纳入平台目录，并按共享范围向已有租户和新租户提供。
  3. 租户管理员查看“平台提供”，可查看当前空间有哪些 Agent 绑定该模型。
  4. 在 Agent 管理详情页选择个人计费模型，“计费方式”使用紧凑下拉框选择“使用提问人额度”或“使用创建人额度”，默认使用提问人；保存后建立绑定并记录额度承担规则。
  5. 用户向该 Agent 提问时，系统按已保存规则确定额度承担人：提问人模式扣实际提问人额度，创建人模式扣该 Agent 创建人额度；不能将当前编辑人、源租户或应用账号当作个人额度承担人。

示例：网易POPO新增一个个人计费模型并设为“全部租户”后，租户甲、租户乙无需新建模型即可选用；若设为“指定租户”且只选甲，则乙不可见、不可选用。默认模式下，甲租户内小王提问扣小王额度，小李提问扣小李额度；若 Agent 配置为“使用创建人额度”，两人的提问均扣除此 Agent 创建人的 Token 额度。

04 平台供给与同步规则

4.1 同步范围与归属

平台模型保持个人计费类型；Agent 可选择使用提问人或创建人额度。

2026-11-02 调整：原“平台个人计费模型固定使用提问人额度、不可修改”的约束已被本次需求替代。Agent 选择任一个人计费模型时均可选择两种个人额度承担方式；这不改变模型的个人计费类型，也不修改其他 Agent 的扣费配置。

  • 供给条件为“源租户是网易POPO”且“计费方式是个人计费”。进入个人计费供给池后，还需按模型共享范围判断目标租户是否获授权，不能在页面写死模型清单。
  • 网易POPO租户下的应用计费模型不进入平台供给目录。其他租户的个人计费模型也不因此自动成为平台模型。
  • 模型名称、标识、接入方式 / 接入方、接口协议、标签、源状态及调用所需配置随源模型更新；平台模型的计费方式固定展示“个人计费”；Agent 侧默认使用提问人额度，并支持选择使用创建人额度。
  • 系统应使用稳定的源模型身份关联平台目录与 Agent 绑定，不能仅按展示名称或模型标识去重。名称相同的自建模型与平台模型分别存在。
  • 同步的是模型使用能力和必要元数据；凭据由服务端安全使用，不向目标租户回显或要求其重新填写。

4.3 模型共享范围

本次新增：网易POPO租户在新建模型页配置模型共享对象。平台不再默认将每个源模型无条件提供给所有租户；模型是否进入某租户的平台目录，由个人计费条件与共享范围共同决定。

目标租户可见 = 网易POPO源模型 ∩ 个人计费 ∩ 共享范围包含该租户

实际调用还需满足模型启用状态、当前用户权限及额度条件。共享范围不改变计费方式与扣费主体。

配置 / 变化产品行为
全部租户覆盖 Studio 当前所有租户，并自动包含后续新增租户；不保存为当前租户 ID 的静态快照。
指定租户仅向勾选的租户提供；未选择的租户不展示该模型，也不能新绑定或调用。后续新建租户不会自动加入。
增加指定租户保存后为新增对象同步模型；已授权对象继续获得最新配置。
移除租户 / 全部改指定保存后撤回范围外租户的供给与调用权限，不改扣其他账号、不自动替换模型。既有 Agent 绑定失效展示、通知和在途请求处理需评审确认。
指定改全部保存后扩展至所有租户，并覆盖未来新增租户。

租户授权须在服务端判断，不能仅靠隐藏列表控制调用权限；同步重试时应用共享范围的最新版本，防止已撤回的租户因旧事件恢复授权。

网易POPO租户的应用计费模型只能由网易POPO本租户使用，不允许共享给其他租户。新建或编辑选择应用计费时，系统自动将共享范围设为“指定租户”，指定租户固定为“网易POPO”；两个字段均置灰不可修改。此规则不改变超管后台独立的使用范围配置。

4.4 一致性要求

同步需可重试、可补偿，重复事件不产生重复记录；过期更新不能覆盖较新配置。单租户同步失败不应阻断其他租户。列表“刷新”用于重新获取数据，不应成为后台同步的唯一触发方式。

新增 / 更新的同步时效、失败告警与补偿周期尚未约定，列入评审项。源端停用或撤回后的调用校验不能仅依赖旧页面状态，以免前端仍展示可用时继续发起无效调用。

06 空间自建模型

空间自建用于补充专属接入或应用账号计费需求。新建操作进入独立页面，包含“01 基本信息”和“02 接入配置”，不使用新建弹窗。网易POPO租户额外展示“03 模型共享”，普通租户不展示。

分组字段规则
基本信息模型名称必填，去除首尾空格后不能为空；原型长度上限 60。
基本信息模型标识必填；原型长度上限 100。
基本信息标签（逗号分隔）选填。
接入配置凭据方式共享 Key / 个人 Key，默认共享 Key；与计费方式是不同维度。
接入配置共享 Key共享 Key 模式显示密码输入；保存后不回显。具体必填条件沿用接入协议。
接入配置接入方个人 Key 模式展示；按用户身份提供凭据，候选与校验沿用现有能力。
接入配置接口协议（Provider）必填，默认 OpenAI 兼容；原型还包含 deepseek、anthropic、custom。
接入配置模型 API 地址必填，校验 URL。
接入配置计费方式个人计费 / 应用计费，原型默认个人计费；对应账号须实际支持选定方式。

个人计费下方展示“扣除提问人Token额度”；应用计费下方展示“扣除申请的应用账号额度”。修改选项立即更新说明。

保存成功返回空间自建列表并显示新模型；取消、返回不保存当前修改。编辑复用同一页面。底部保留“凭据保存后不回显”提示。

凭据方式不能推导计费方式：共享 Key 不必然等于应用计费，个人计费也不要求租户手动填写个人 Key。最终可选组合及账号验证应由现有接入能力约束，不能仅凭前端枚举决定实际扣费主体。

6.1 新增“03 模型共享”

重点：网易POPO应用计费模型仅限本租户使用。

计费方式为“应用计费”时，自动设置“共享范围：指定租户”“指定租户：网易POPO”，均置灰锁定；清除其他已选租户并关闭多选面板。提示：“应用计费模型仅限网易POPO租户使用，不支持共享给其他租户。”

切回“个人计费”时解除锁定，保留当前“指定租户 → 网易POPO”值，管理员可重新选择全部租户或其他指定租户；不自动恢复之前的跨租户共享范围，避免无意扩大授权。新建、编辑回显及保存均执行同一约束。服务端须校验并拒绝应用计费模型向非网易POPO租户共享的请求，不能只依赖前端置灰。

个人计费模型改为应用计费后，保存须撤回其他租户的供给与调用权限；已绑定 Agent 的失效展示及在途请求处理沿用共享范围收缩的待评审规则。未保存的表单切换不改变线上授权。

仅网易POPO租户展示，位置在“02 接入配置”下方、保存操作区上方；编辑模型时回显已保存的共享范围及指定租户。

字段枚举 / 数据来源交互与校验
共享范围全部租户、指定租户必填。个人计费默认“全部租户”；网易POPO应用计费自动固定为“指定租户”，不可修改。
指定租户Studio 当前全部租户，包含网易POPO；以稳定租户 ID 保存，名称用于展示仅当共享范围为“指定租户”时动态展示，使用下拉多选样式：顶部搜索框、单列复选项、已选行灰底高亮与蓝色勾选；收起后显示已选租户名称。支持名称搜索，至少选择 1 个租户。
  • 切换为“指定租户”即时显示多选控件，搜索不清除已选项，并显示已选数量。
  • 切换为“全部租户”隐藏指定租户字段且不校验该字段；保存时不提交过期指定列表。当前未保存表单内切回“指定租户”保留先前勾选，方便调整。
  • 保存时服务端重新校验租户 ID 存在且可用；租户已删除、列表加载失败等情况应提示并允许重试，不能将失败误作“全部租户”。
  • 新建或编辑保存成功后共享配置生效并触发供给更新；取消不改变已保存配置。
  • 普通租户的新建 / 编辑页面不显示共享模块，也不能通过提交共享字段获得平台供给权限。

当前单文件原型新增顶部租户切换，用于演示网易POPO的配置与接收租户的可见差异。租户选项为本地模拟目录；生产需接入 Studio 完整租户数据，支持加载完整候选，不能只列出前端写死的租户或首屏数据。

07 Agent 配置与计费链路

7.1 页面展示与交互

应用计费沿用只读“应用计费”展示，不展示个人额度选择。扣除申请的应用账号额度

7.2 默认值、保存和回显

  • 首次选择一个人计费模型，默认“使用提问人额度”。模型的个人 / 应用计费类型由模型配置决定，Agent 页面仅选择个人计费情况下的额度承担人。
  • 下拉选择立即更新提示，并将 Agent 标记为“配置未保存”；不立即更改线上绑定或发生扣费。点击“保存配置”后，模型绑定和额度承担方式一并保存。
  • 重新进入已保存配置时回显保存值。原型仅在当前演示会话内保留数据；正式产品须持久化。
  • 切换到另一个未保存过的个人计费模型时恢复默认提问人；切回当前已保存绑定的模型时回显其已保存额度承担方式。保存到新模型后以新绑定为准。
  • 切换为应用计费时隐藏个人额度选项，保存不携带有效个人额度承担配置；继续使用该模型绑定的应用账号。
  • 修改只影响当前 Agent，不改写模型定义，也不批量改变其他 Agent 的额度承担配置。

7.3 费用归属

配置实际扣费主体说明
使用提问人额度当前调用的实际提问人不同提问人分别使用自己的 Token 额度。
使用创建人额度此 Agent 的创建人所有提问统一使用创建人额度；“创建人”不是当前登录编辑者，也不是模型创建人或平台管理员。
应用计费模型配置对应的应用账号沿用当前逻辑；不因个人额度充足而自动改扣个人。

个人额度承担方式应存储在 Agent 配置层，由服务端读取 Agent 创建人身份和调用人身份确定账户，不能由请求随意指定其他用户。身份无法识别或相应额度不可用时按现有服务明确返回失败，不自动改扣另一方或应用账号。

本期不改变 Token 单价、扣减计算或失败请求的底层结算规则。创建人离职、停用或 Agent 所有权转移的处理尚未确认，需评审后明确，不能用当前编辑人自动替代创建人。

08 超管后台 · 模型管理

8.1 入口与页面范围

入口为平台管理（超管后台）→ 能力管理 → 模型。列表保留“模型列表 / 接入方”两个 Tab，右上角提供“新建模型”。本期修改模型列表与新建 / 编辑表单，接入方管理维持原能力。

超管使用范围与网易POPO租户的“03 模型共享”是不同入口：前者面向平台管理员，使用“05 使用范围”；后者保留原租户侧设计。超管本次能力同时覆盖后台已有个人额度和应用额度模型，不能将网易POPO个人计费供给池的准入条件直接套到超管全部记录。

8.2 新建 / 编辑页面

保留“01 基本信息”“02 接入配置”“03 展示设置”“04 可见性规则”。新增“05 使用范围”，置于可见性规则之后、高级配置之前。

模块 / 字段要求

JSON 输入必须为合法 JSON 对象；校验失败时自动展开高级配置并提示错误。取消不提交修改。编辑回显使用范围、租户列表、入口、JSON 和其余共享字段。

8.3 每租户一条记录，共享同一配置

一份模型配置 + 多个租户关联 = 列表中的多条归属租户记录。

列表按租户拆行，不复制出可独立修改的多份模型定义。每条记录关联同一个稳定模型配置 ID。

  • 指定租户 A、B：保存后新增两条列表记录，归属租户分别为 A、B；模型名称、标识、协议、展示、计费方式、标签、状态、使用入口、参数等共享同一配置。
  • 选择全部租户：按 Studio 全部当前租户分别生成记录；新增租户是否自动补齐按共享范围原则处理，建议与前述全租户持续供给一致。
  • 从任一归属租户记录进入编辑，编辑的是共享配置，保存同步影响同一配置关联的全部租户。保存区明确提示“保存将同步更新该模型所有归属租户的配置”。
  • 编辑指定租户集合时按差量增删关联；新增租户增加一行，移除租户撤去一行，保留租户不重复创建。
  • 模型配置 ID 与租户 ID 的组合唯一，重复保存、同步或重试不能产生重复行。不同模型配置即使名称相同也不能合并。

示例：模型 M 共享给网易POPO、研发中心、客户服务，列表显示 3 行。由研发中心行把 M 的名称改为 M2 后，3 行均显示 M2；并非仅修改研发中心的一行。

归属租户新增字段，每一行只展示一个租户名称。

8.5 原型边界与待确认规则

原型已实现超管列表、表单、租户拆行、共享编辑及筛选，但仍是内存数据，未接真实租户目录、凭据服务或生产授权。平台管理与租户页面间的真实跨后台同步尚未实现。

当前原型删除某行会移除该租户关联，保留其他租户；全部范围删除某租户会转为剩余租户的指定范围。此删除语义未由本次需求明确，须评审确认，特别是“全部租户”的排除策略及已绑定 Agent 的处理。真实删除与范围撤回不可只删展示行而保留调用授权。

模型使用入口控制在哪些产品入口提供模型候选；使用范围控制哪些租户获授权，两者需同时满足，不能互相替代。已绑定 Agent 在取消某入口后是否继续执行，沿用现有能力并在联调时确认。历史无入口配置的模型，编辑保存时必须补选；历史数据批量迁移方式另行评审。

09 权限与原型待收敛项

当前 HTML 是交互原型，使用内存示例数据；未实现后台同步、真实鉴权、凭据保存和实际扣费。页面可交互不能视为这些能力已实现。

事项当前原型PRD 建议 / 待确认
平台模型编辑 / 删除平台行与自建行均展示编辑、删除，使用相同本地修改逻辑。与“源端统一同步”存在冲突。建议平台源字段仅由网易POPO授权管理员维护；目标租户隐藏或禁用编辑、删除。是否保留本地覆盖需产品确认。
平台模型启用 / 停用原型仅修改本地状态，无作用域。建议租户侧操作只控制本租户或当前空间的可用性，不修改源模型、不影响其他租户；具体作用域需确认。源停用优先于本地启用。
平台同步与本地设置原型没有版本或同步状态。如允许本地停用，建议与源状态分开保存，源更新不重置本地选择；平台配置仍以源端为准。
租户 / 空间可见范围原型仅模拟当前空间。租户可见范围按共享配置判定；租户内空间可见与操作范围需结合现有角色权限确认。
绑定模型被删除原型可删除并自动改选其他模型。建议阻止删除仍被绑定的自建模型，先展示绑定并要求解除；平台撤回按失效处理，不静默迁移。
计费方式修改原型允许直接修改。建议修改已绑定自建模型的计费方式前提示影响；是否需要重新确认发布，纳入评审。
本节待确认项与超管后台操作分开评审：超管有权维护共享配置，不表示目标租户获得源配置修改权限。不能将目标租户对平台模型的本地修改反向写入网易POPO。

11 评审决策与上线观察

需收敛的决策

  1. 超管按租户拆行后的删除语义、全租户排除规则，以及超管目录与网易POPO源目录相同模型的去重关系。
  2. 超管跨租户可见部门 / 人员 / Bot 候选来源与失效处理；模型使用入口历史空值的迁移方式。
  3. 共享范围收缩时，既有 Agent 的失效展示、管理员通知和在途请求处理；历史未配置共享范围的源模型建议按“全部租户”迁移，需上线前确认。
  4. 平台行“编辑、删除”是否仅对源租户管理员开放；租户侧停用究竟作用于整个租户还是当前空间。
  5. 源停用、删除、计费方式变化的失效展示、已有 Agent 调用行为与恢复规则。
  6. 同步时效目标、失败补偿周期，以及新租户初始化完成条件。
  7. 个人身份到额度账号的映射范围；用户跨租户使用时的额度归属，以及创建人离职、账号失效或 Agent 转移归属时的处理。
  8. 空间自建已绑定模型的删除限制与计费方式变更确认机制。

上线顺序建议

先完成源目录识别与身份计费验证，再按共享范围初始化已有租户目录，接入持续同步与新租户初始化，最后开放前端双 Tab 与 Agent 选用。已有自建模型和 Agent 绑定保持原状，不能仅凭模型同名自动迁移至平台目录。

上线后观察

关注平台目录覆盖率、同步成功率与延迟、首次绑定平台模型的耗时、调用成功率，以及个人计费归属异常。具体阈值在研发评审时确定，不以原型示例数量作为上线目标。

依据：本轮已确认需求与 模型与计费交互原型。文档中的“建议 / 待确认”为同步与权限边界的补充设计，不表示已获确认。
